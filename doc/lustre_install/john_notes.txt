Brian installed CentOS 8.2 brand-new on in16.

Got an error with the AppStream yum repo so made a few changes:
In /etc/yum.repos.d/CentOS-Linux-BaseOS.repo, I did this:
#mirrorlist=http://mirrorlist.centos.org/?release=$releasever&arch=$basearch&repo=BaseOS&infra=$infra
baseurl=http://vault.centos.org/$contentdir/$releasever/BaseOS/$basearch/os/

And in /etc/yum.repos.d/CentOS-Linux-AppStream.repo, I did this:
#mirrorlist=http://mirrorlist.centos.org/?release=$releasever&arch=$basearch&repo=AppStream&infra=$infra
baseurl=http://vault.centos.org/$contentdir/$releasever/AppStream/$basearch/os/

I was able to upgrade the kernel very easily:
> sudo yum install kernel-4.18.0-348.el8
> sudo grub2-mkconfig -o /boot/grub2/grub.cfg
> sudo reboot

# then you might want to install ansible and ansible is weird with python3.6
# on in15, I was able to somehow install ansible with python3.6

# Then install libvirt
Following these instructions:
https://phoenixnap.com/kb/install-kvm-centos
> sudo yum update
> sudo yum install @virt
> sudo systemctl enable --now libvirtd
> sudo yum -y install virt-top libguestfs-tools
> Then run this https://gitlab.newmexicoconsortium.org/jbent/tassi/-/blob/main/scripts/set_bridge.sh for the bridge stuff
> might also need: sudo dnf install virt-install
> then you can install vm's 

For easier host-resolution:
> sudo dnf install libvirt-nss
Edit /etc/nsswitch.conf to change the hosts: line to add libvirt libvirt_guest
Test with getent hosts [domain_name]

Then the default location for /var/lib/libvirt is in a small disk partition. So do this:
> sudo mkdir /home/libvirt
> sudo mv /var/lib/libvirt/images /home/libvirt
> sudo ln -s /home/libvirt/images/ /var/lib/libvirt/

Then use https://gitlab.newmexicoconsortium.org/jbent/tassi/-/blob/main/scripts/setup_VM_batch.sh to set up a vm
called freshinstall. 

Then dnf install python38 and python38-devel and libvirt-devel. Then 
> sudo dnf groupinstall "Development Tools"
> sudo pip38 install -r requirements.txt (https://gitlab.newmexicoconsortium.org/jbent/tassi/-/blob/main/scripts/requirements.txt

Then everything can be done by defining an ansible inventory file. 

The user creates an ansible inventory file like this one:
> https://gitlab.newmexicoconsortium.org/jbent/tassi/-/blob/main/scripts/ansible/hosts.small_lustre.yaml

Everything is defined in this one single file including configure options for building lustre, the particulars of the interconnect, how many servers and clients and how large the hard drives should be.  The current config defines 1 client, 2 mds, and 2 oss

Then, the user passes that file to a script which uses the libvirt python module to set up VMs, install, configure, and test a lustre cluster
> https://gitlab.newmexicoconsortium.org/jbent/tassi/-/blob/main/scripts/setup_lustre_cluster2.py
